# 录屏演示：不改代码，了解并调整生活参数

在独立 SurfCore 衍生仓库运行：

```powershell
npm run demo:life
```

如需每阶段停下来讲解，使用：

```powershell
npm run demo:life -- --step
```

等价直接入口是 `node scripts/demo-life-settings.mjs`。`--help` 只打印说明，不启动演示。

## 观众看到什么

1. 真实 MCP stdio 客户端连接本项目 `src/mcp-life-settings.js`，发现同一组正式工具并查询状态。此时没有消费者证据，实际值为未知。
2. Agent 工具发现 B站生活参数，并解释每日机会的窗口、概率、最小间隔、预算与登录等依赖。
3. **明确标为脚本化 Agent 选择**：预览“增加自主浏览机会”。计划会联动每日机会、窗口容量和单次浏览量；预览后设置修订仍为0。
4. 显式提交后变为r1，立即验证仍返回 `saved-unverified`。
5. 真正运行 B站 scheduler 的 `tick()`，由它调用实际 planner 子进程读取隔离配置、生成随机日程并发布运行证据。工具再次验证为 `runtime-adopted`，范围明确是 `local-simulation`，同时显示保存值、消费者采用值、下一次计划及已用次数。
6. 记录观察与考虑恢复的决定，历史保留理由、前后值和证据位置。
7. 预览回滚、显式提交、再次运行消费者并验证r2。每日机会恢复1次，已用次数不归零。
8. 停止本次调度器。最后查询明确显示运行时已停止；历史采用证据仍保存在文字稿里，不把停止后的配置当在线验收。

可用旁白：“她先知道自己能改什么，再看修改会联动哪些条件。写盘成功时，系统没有急着说生效；等真正的调度器读到并采用新值，才给出带来源的验证。之后还可以恢复原来的设置。”

## 哪些是真实实现，哪些是隔离模拟

真实使用的是正式 MCP schema、参数目录、耦合校验、事务保存、历史、回滚、B站 planner 子进程与 scheduler 采用点。演示脚本不直接写运行采用证明，不使用固定假工具返回。

模拟的是 Agent 的选择和 DSH prompt 接收端。选择由脚本明确给出，没有调用付费模型；调度器产生的 prompt 只进入本地收集器，没有执行里面的工具，也不登录或发送任何QQ/B站消息。没有唤醒真实大肥鱼，不能把这段录屏表述为她本人已经形成了某项兴趣或自主选择。

每次运行创建独立 `state/life-demo/<时间戳-随机ID>/`。其中包含隔离root/home、实际配置与计划、完整 `transcript.json`、适合讲解的 `transcript.md` 和 `demo-report.json`。没有复制用户凭据、人设、原始记忆或其他生命的数据。评论/私信/直播监听、动态和自动分享都在这个隔离配置内关闭。

日程按真实本地时钟和随机规划产生，下一次时间不是固定输出。当天最后时窗已经结束时，真实计划可能显示没有剩余机会；不要为录屏把它改成固定“成功浏览”结果。已采用的配置、已生成的计划、已投递本地任务、实际平台动作是不同证据。

脚本结束会清理自己启动的MCP子进程和调度器定时器，隔离证据保留供回看。真实平台登录、真实 Agent 会话中的本人决定、官方模型 wire/缓存与平台账单仍需后续授权后独立验收。
